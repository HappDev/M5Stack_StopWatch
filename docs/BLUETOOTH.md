# Bluetooth-клавиатура StopWatch OTP

Статус аппаратных испытаний: **не выполнены**. Native-тесты и рендер LVGL не подтверждают совместимость с конкретным Bluetooth-адаптером, ОС или физическим StopWatch.

## Подключение

1. Обновите приложение с сохранением хранилища: `python tools/flash.py --update --port COM7`. До обновления сохраните резервную копию. Для первой установки используйте factory-образ; поверх существующего хранилища его не устанавливайте.
2. Разблокируйте StopWatch. Откройте «Настройки» → «Bluetooth» → «Включить» → «Сопряжение».
3. В Windows откройте настройки Bluetooth и добавление устройства; на macOS — «Системные настройки» → Bluetooth. Выберите `StopWatch OTP`.
4. Сравните шестизначные числа. Подтвердите совпадение на StopWatch и на компьютере. При несовпадении нажмите «Отмена».
5. Дождитесь надписи «Bluetooth подключён». На ПК установите курсор в нужное поле и откройте аккаунт касанием строки списка StopWatch.

Для нового сопряжения требуется физическое действие после разблокировки. Экран остаётся включённым в течение окна 60 секунд; блокировка и отмена закрывают окно. Неподтверждённое число, истечение срока или неподдерживаемый способ сопряжения не разрешают ввод. Используются BLE Secure Connections с MITM-защитой, 16-байтным ключом и проверкой числа; автоматического принятия или общего PIN нет.

Если ПК предлагает только ввод PIN, не показывает сравнение числа или не завершает защищённое подключение, этот сценарий требует отдельной проверки совместимости: прошивка не переключается на незащищённый режим. При необходимости повторного сопряжения удалите старую запись на обеих сторонах.

В Parallels при сопряжении с macOS ввод следует фокусу Mac: для ввода в Windows активируйте поле в окне виртуальной машины. При передаче отдельного Bluetooth-адаптера виртуальной машине сопряжение выполняется внутри Windows. Эти сценарии пока не проверялись на аппаратуре.

## «Ошибка Bluetooth» сразу после включения

В первой версии BLE-клавиатуры обнаружена ошибка настройки объявления: в `esp_ble_gap_config_adv_data` передавался двухбайтовый UUID HID `0x1812`. ESP-IDF 5.5.4 принимает здесь UUID в полном 128-битном представлении и возвращает `ESP_ERR_INVALID_ARG` для длины 2. Это прерывает создание сервисов ещё до сопряжения. Исправление передаёт тот же HID UUID через Bluetooth Base UUID в массиве из 16 байт; короткий UUID в таблице GATT остаётся корректным.

Для установленной прошивки обновите только приложение из исправленного комплекта: `python tools/flash.py --update --port COM7` (замените порт). Затем включите Bluetooth и откройте «Сопряжение». Сброс хранилища для этого исправления не требуется. Если ошибка остаётся, значит есть дополнительный сбой запуска: общий статус сам по себе не указывает, какой вызов завершился ошибкой.

## Ввод

| Действие | Результат |
|---|---|
| Открыть аккаунт касанием строки списка | Один ввод текущего кода |
| Нажать на крупные цифры в карточке | Повторный ввод текущего кода |
| Переключить аккаунт жёлтой кнопкой | Открытие следующего аккаунта без ввода |
| Прокрутить список, дождаться нового TOTP, обновить экран | Ввод не запускается |
| Разбудить экран, разблокировать, восстановить связь | Ввод не запускается |
| Нажать без связи или с неверным RTC | Сообщение на экране, без очереди на будущее |
| Нажать ещё раз во время отправки | Текущая отправка продолжается без второго запуска |

Передаются только цифры, включая начальные нули. Секрет TOTP, названия аккаунтов и команды USB-протокола по Bluetooth не передаются. Код печатается в поле с текущим фокусом, без проверки сайта и без нажатия Enter. Повторное нажатие дописывает цифры; поле перед повтором нужно очистить самостоятельно, если приложение не делает этого само.

При обрыве или блокировке уже введённые цифры остаются в поле, оставшаяся часть отменяется. После восстановления связи автоматического повтора нет. Очистите неполный ввод и нажмите на код повторно. Надпись «Код отправлен» означает успешную передачу HID-отчётов стеку Bluetooth; устройство не получает подтверждение содержимого поля приложения.

## Хранение связи и питание

Хранится одно сопряжение и настройка включения. Подписки HID сохраняются для этого компьютера и восстанавливаются только после повторной аутентификации. Для смены ПК служит «Забыть компьютер». Полный сброс удаляет аккаунты и сопряжение, выключает Bluetooth. Обычная блокировка прекращает передачу и сопряжение, но сохраняет установленное соединение с известным компьютером.

Экран гаснет после 30 секунд без действий; при включённом Bluetooth процессор продолжает обслуживать соединение с modem-sleep контроллера. Принудительный CPU light-sleep применяется только при выключенном Bluetooth. Предел разблокировки остаётся 12 часов. Фактическое энергопотребление и время работы требуют измерения.

## Реализация

Используются Bluedroid и разбор стандартного дескриптора клавиатуры компонентом `esp_hid` из ESP-IDF 5.5.4. Стандартные HID/GATT-характеристики реализованы через публичный GATTS API. Это позволяет отправлять уведомления без блокирующего ожидания семафора внутри `esp_hidd_dev_input_set`. Поддерживаются Report Protocol и Boot Keyboard, LED Output и HID Control Point. Добавлены Device Information с PnP ID, соответствующим USB-дескриптору этой прошивки, и включённый Battery Service. Процент батареи — приблизительная оценка по напряжению 3,3–4,2 В. Bluetooth callbacks обновляют защищённый снимок состояния; LVGL и хранилище обслуживаются главным циклом. Состав профиля сверяется с [HOGP ICS](https://files.bluetooth.com/wp-content/uploads/2024/10/HOGP.ICS.p8.pdf).

Каждая цифра — отдельные нажатие и отпускание с интервалом не менее 20 мс. Новый ввод требует защищённого соединения и подписки на HID-уведомления. Смена соединения, режима протокола или потеря подписки отменяют текущую последовательность. Временный буфер кода стирается после завершения или отмены. Инициализация и очистка Bluetooth не форматируют NVS, не меняют eFuse и не меняют формат зашифрованного хранилища.

При включённом контроллере Bluetooth генерация ключей и nonce использует RF-источник энтропии через `esp_fill_random`. При выключенном радио временно включается прежний SAR-источник. Одновременное включение этих источников запрещено API ESP-IDF и отдельно проверяется native-тестом.

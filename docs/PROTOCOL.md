# USB и форматы данных, версия 1

## Транспорт

USB CDC-ACM (TinyUSB), браузер открывает Web Serial со скоростью 115200 и DTR=true. Для USB CDC это номинальное значение, не физическая скорость UART. На стороне прошивки нет команд ввода графического ключа или прежнего PIN, получения кода TOTP или удалённого разрешения USB.

Запрос и ответ — UTF-8 JSON, завершающийся `\n`. Весь кадр вместе с `\n` не более 4096 байт. Нулевой байт запрещён. После переполнения данные отбрасываются до следующего `\n`; следующий корректный кадр снова обрабатывается. Неполный кадр старше трёх секунд отбрасывается. Глубина JSON ограничена шестью уровнями, повторяющиеся ключи объектов отклоняются. Запросы выполняются последовательно.

```json
{"v":1,"id":1,"op":"list","args":{"offset":0}}
```

```json
{"v":1,"id":1,"ok":true,"result":{"total":0,"records":[]}}
```

```json
{"v":1,"id":1,"ok":false,"error":{"code":"LOCKED","message":"Разблокируйте StopWatch и разрешите USB"}}
```

`id`: целое 1…2147483647; `v`: строго 1. Ошибка неподдающегося разбору кадра имеет `id:0`. Возможные коды ошибок: `FRAME`, `INPUT`, `LOCKED`, `BUSY`, `CANCELLED`, `STATE`, `FAILED`, `UNKNOWN`.

Только `status` и `lock` доступны без разрешения. Все остальные команды требуют завершённого перехода на графический ключ, разблокировки и физического включения USB-управления. Подключение, снятие DTR, блокировка и разрыв соединения отменяют сеанс. Физическое бездействие 30 секунд блокирует устройство; входящие команды это время не продлевают. Незавершённые передачи истекают через 15 секунд между сообщениями; время ожидания физического подтверждения не считается межкадровым тайм-аутом.

## Команды

| Команда | Аргументы | Ответ и подтверждение |
|---|---|---|
| `status` | `{}` | `firmware,state,authorized,timeValid,time,batteryMv,retryAfter`; без разблокировки |
| `lock` | `{}` | Блокирует устройство и закрывает USB-доступ |
| `list` | `offset:0…100` | До пяти записей без секретов, `total,records` |
| `upsert` | `record` | Добавляет или заменяет запись по UUID; подтверждение на экране |
| `rename` | `id,issuer,account` | Меняет только название; подтверждение |
| `delete` | `id` | Удаляет запись; подтверждение |
| `time_set` | `epoch` | UTC Unix seconds, 2000…2099; подтверждение |
| `export_begin` | `{}` | Подтверждение передачи всех секретов, затем `count` |
| `export_next` | `{}` | Одна запись с секретом в `record`; один проход по набору |
| `restore_begin` | `count:0…100` | Начинает новый набор в оперативной памяти |
| `restore_item` | `index,record` | Индекс строго последовательный, начиная с нуля |
| `restore_commit` | `{}` | При полном наборе запрашивает подтверждение полной замены и атомарно сохраняет его |
| `restore_abort` | `{}` | Очищает промежуточный набор и состояние экспорта |

Секреты при экспорте передаются по доверенному USB в память браузера. На HTTP-сервер они не поступают. Потеря ответа не означает, что операция не выполнена: после тайм-аута перечитайте список. Повторный `upsert` с тем же UUID не создаёт ещё одну запись. После обрыва экспорта/восстановления начните передачу заново.

`time_set` учитывает монотонно измеренную задержку подтверждения: устройство устанавливает переданный Unix timestamp плюс время ожидания пользователя. Сайт не может передать собственное значение этой поправки.

## Запись аккаунта

```json
{
  "id":"12345678-1234-4234-8234-123456789abc",
  "issuer":"Example",
  "account":"alice@example.com",
  "secret":"GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ",
  "algorithm":"SHA1",
  "digits":6,
  "period":30
}
```

UUID — 36 символов, строчные шестнадцатеричные цифры и дефисы. Названия — корректный UTF-8 без управляющих символов, 96/128 байт, хотя бы одно из них непустое. Секрет Base32 декодируется в 10…128 байт; некорректная длина, padding и ненулевые завершающие биты отклоняются. Алгоритм — SHA1/SHA256/SHA512, цифры — 6/8, период — 30/60. В списке `secret` отсутствует. Восстановление отклоняет повторяющиеся UUID до сохранения.

## Файл .otpvault

UTF-8 JSON размером не более 256 КиБ:

```text
format: "stopwatch-otp"
version: 1
kdf: "PBKDF2-SHA256"
iterations: 600000
salt: Base64(16 случайных байт)
cipher: "AES-256-GCM"
nonce: Base64(12 случайных байт)
ciphertext: Base64(шифротекст || 16-байтный тег)
```

Пароль — UTF-8 без неявной Unicode-нормализации, от 16 символов до 1024 байт. Ключ — PBKDF2-HMAC-SHA256, 600000 итераций, 256 бит. Поле `ciphertext` шифрует `{"version":1,"records":[...]}`. AAD — `JSON.stringify` объекта с полями в указанном порядке: `format,version,kdf,iterations,salt,cipher,nonce`, без пробелов. При расшифровке этот заголовок восстанавливается в том же порядке; лишние поля и другие параметры отклоняются до KDF. Файл не связан с графическим ключом или аппаратным идентификатором устройства.

## Снимки во Flash

Разделы `vault_a` и `vault_b` по 512 КиБ. Никаких открытых записей, рисунка, PIN или ключей шифрования в них нет. Каждый снимок содержит packed little-endian 136-байтный заголовок формата 1 или 2, номер поколения, количество записей, длину, параметры KDF, соль, nonce/шифротекст/тег обёртки ключа и nonce/тег данных. Случайный 256-битный ключ данных заворачивается ключом PBKDF2-HMAC-SHA256 (600000 итераций). В формате 1 вход KDF — прежний PIN из 8–12 цифр; в формате 2 — ASCII-строка `StopWatch/Pattern/v1:` и последовательность из 4–6 разных символов `1`–`9` без завершающего NUL. Нумерация точек идёт слева направо, сверху вниз; незадействованная промежуточная точка должна входить в последовательность перед конечной. Размеры заголовка и записей не меняются. AAD обёртки — байты `StopWatch/DEK/v1` с завершающим NUL. AAD данных — байты заголовка до поля тега данных. Полезная нагрузка — `count` фиксированных записей по 396 байт; изменение этого layout требует новой версии формата.

CRC32 заголовка и шифротекста служит для обнаружения незавершённой записи до ввода ключа; криптографическую целостность обеспечивает GCM. Незаписанный раздел имеет все байты 0xff. Сначала стирается неактивный раздел, записываются заголовок и шифротекст, проверяется чтением, последним записывается четырёхбайтный маркер commit в конце раздела. Предыдущий снимок сохраняется. На старте выбирается исправный снимок с наибольшим поколением.

Отдельный NVS хранит только счётчик попыток. Попытка фиксируется до проверки ключа, поэтому отключение питания во время KDF не сбрасывает её. На перезагрузке полная задержка текущего уровня начинается заново. С пятой неудачной попытки: 30, 60, 120, 240, 480, 960, 1920, 3600 секунд; далее один час. Ошибка записи счётчика закрывает доступ. Автоматического удаления аккаунтов нет.

При переходе с формата 1 прежний PIN только расшифровывает данные для настройки нового рисунка. До её завершения `status` сообщает `state:"locked", authorized:false`; другие команды отклоняются. При успешном переходе или смене ключа оба снимка перезаписываются с новой обёрткой. При обрыве выбирается снимок с наибольшим подтверждённым поколением и соответствующий ему способ входа; после неверного ключа переход к старому снимку не выполняется. При смене ключа USB-разрешение и незавершённые передачи отзываются.
